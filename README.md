# RAG Document Chatbot — Lisa

Upload large documents (PDF, DOCX, TXT, MD), ask questions, get natural answers
grounded in the document content. Ships with a React chat UI ("Lisa") and a
FastAPI backend; the API also returns a structured `sources` array for any UI
that wants to show references.

**Stack:** React + Vite · FastAPI + LangChain · **Gemini** for the LLM ·
**Pinecone** for embeddings (hosted inference) *and* vector search.

No local model server, no local vector DB, no OpenAI/Mistral keys. Just two
managed services: Google AI and Pinecone.

## Features

- **Large-document ingestion** — streamed uploads (size-limited), extension
  validation, PDF page numbers preserved.
- **Chunking + retrieval** — `RecursiveCharacterTextSplitter` (configurable
  size/overlap), top-k vector search per query.
- **Grounded answers** — retrieved chunks are stuffed into a LangChain prompt;
  the response includes the sources (filename, chunk index, snippet, score).
- **Persona** — the assistant is **Lisa**, a friendly female AI chatbot. She
  knows she is a chatbot (not a human) and handles greetings / identity
  questions naturally; rename her with `CHATBOT_NAME`.
- **Ready-made web UI** — React + Vite chat app with document upload
  (drag-and-drop), document list/delete, connection status and model info.
  Served by nginx, which proxies `/api` to the backend container (same origin,
  so no CORS headaches in the browser).
- **Pinecone hosted embeddings** — embeddings are generated by Pinecone's
  inference API (`llama-text-embed-v2` by default); no separate embedding
  provider to configure.
- **Real deletion** — chunk ids are `{doc_id}:{chunk_index}`, so deleting a
  document removes its vectors from Pinecone.
- **Stateless chat** — the client may send an optional `history` array; the
  server keeps no session state.
- **Offline test mode** — `PROVIDER=fake` swaps in deterministic stubs; the test
  suite runs with no keys and no network.

## Architecture

```
  browser (React SPA served by nginx)
     │  /api/* proxied to the backend container
     ▼
  FastAPI backend
     ├─ ingest: loader → chunker → Pinecone inference embed → Pinecone index
     └─ query:  embed question → top-k search → Gemini → answer + sources[]
```

- **Frontend:** `frontend/` — React + TypeScript + Vite. In production nginx
  serves the static bundle and reverse-proxies `/api` to the backend; in dev the
  Vite server proxies `/api` to `http://localhost:8000`.
- **Ingestion:** upload → parse (LangChain loaders) → chunk → embed (Pinecone
  inference, `input_type="passage"`) → upsert vectors into the index.
- **Query:** embed the question (`input_type="query"`) → Pinecone top-k search →
  build a context prompt → Gemini → answer + sources.
- **Manifest:** a small local JSON file tracks uploaded documents for listing
  and deletion (`storage/vectorstore/<embedding-model>/manifest.json`).

## Prerequisites

1. **Google AI Studio key** — <https://aistudio.google.com/apikey>
2. **Pinecone account + API key** — <https://app.pinecone.io>
3. A Pinecone index (one-time, see below)
4. Either **Docker Desktop**, or **Python 3.12+** for local backend runs and
   **Node.js 20.19+ / 22.12+** for local frontend runs

### Create the Pinecone index (one-time)

Create a **serverless** index with **metric `cosine`** and a **dimension that
matches the embedding model**:

| `PINECONE_EMBEDDING_MODEL` | Dimension |
|---|---|
| `llama-text-embed-v2` (default) | **1024** |
| `multilingual-e5-large` | **1024** |

> Use a regular ("custom") dense index — **not** an index created with
> "integrated embedding". This app embeds through Pinecone's inference API and
> upserts the vectors itself.

`PINECONE_NAMESPACE` is optional (empty = the default namespace); use it to keep
several datasets in one index.

### Finding your index name (or just use the host)

The app accepts **either**:

- `PINECONE_INDEX=<index name>`, or
- `PINECONE_HOST=<index host URL>` — e.g.
  `https://chat-bot-idx-b8h006u.svc.aped-4627-b74a.pinecone.io`

Pinecone hostnames are `{index-name}-{project-id}.svc.{environment}.pinecone.io`,
so the host above belongs to the index **`chat-bot-idx`** (don't include the
`-b8h006u…` suffix in the name).

To list every index with its name, dimension, metric and host:

```powershell
# from the repo root, using the backend venv
backend\.venv\Scripts\python.exe -c "from pinecone import Pinecone; pc = Pinecone(api_key='YOUR_KEY'); [print(i.name, i.dimension, i.metric, i.host) for i in pc.list_indexes()]"
```

Or open <https://app.pinecone.io> → **Indexes** — the name is the first column,
and the host is under the index's details.

## Run with Docker

```bash
# repo root
cp .env.example .env             # fill in keys (or export env vars)
docker compose up --build
```

- **UI:** <http://localhost:3000>
- **API:** <http://localhost:8000> (Swagger UI at `/docs`)

Or pass everything inline:

```bash
GOOGLE_API_KEY=... PINECONE_API_KEY=... PINECONE_INDEX=chat-bot-vectors \
  docker compose up --build
```

Useful variations:

```bash
# Different host ports
FRONTEND_PORT=8080 BACKEND_PORT=8001 docker compose up --build

# Different Gemini model
GOOGLE_CHAT_MODEL=gemini-2.5-pro docker compose up --build

# Offline fake mode (no keys; useful to check the API plumbing)
PROVIDER=fake docker compose up --build

# Stop / wipe local uploads + manifest
docker compose down
docker compose down -v
```

> Compose starts two containers: `frontend` (nginx serving the built React app)
> and `backend` (FastAPI). Gemini and Pinecone are external managed services.
> The `chatbot-data` volume persists uploads and the document manifest, and the
> frontend waits for the backend healthcheck before starting.

## Run the frontend locally (dev)

The dev server proxies `/api` to `http://localhost:8000`, so start the backend
first (Docker or uvicorn).

```bash
cd frontend
npm install
npm run dev        # http://localhost:5173
```

Production build: `npm run build` (output in `frontend/dist`). The Docker image
does this automatically and serves the result with nginx.

Set `VITE_API_BASE_URL` at build time only if the API lives on a different
origin; leave it unset for the same-origin `/api` proxy.

The bundled UI deliberately **does not** render the `sources` array — Lisa's
answers never point back to uploaded documents. The data is still in the API
response if you want to show references in your own frontend.

## Configuration

Settings come from `backend/.env` (local) or the environment (Docker). All
values are optional except the two service keys and the index name.

| Variable | Default | Notes |
|---|---|---|
| `PROVIDER` | `gemini` | `gemini` or `fake` (offline stubs) |
| `CHATBOT_NAME` | `Lisa` | assistant persona name (the bot introduces itself as a female AI chatbot) |
| `FRONTEND_PORT` | `3000` | host port for the UI (Docker Compose) |
| `BACKEND_PORT` | `8000` | host port for the API (Docker Compose) |
| `VITE_API_BASE_URL` | — | build-time API origin for the UI; leave unset for the same-origin `/api` proxy |
| `GOOGLE_API_KEY` / `GEMINI_API_KEY` | — | required for `gemini` |
| `GOOGLE_BASE_URL` / `GEMINI_BASE_URL` | — | only for proxies/gateways |
| `GOOGLE_CHAT_MODEL` / `GEMINI_CHAT_MODEL` | `gemini-2.5-flash` | e.g. `gemini-2.5-pro` |
| `PINECONE_API_KEY` | — | required |
| `PINECONE_INDEX` | — | index name; must pre-exist, dimension must match the embedding model |
| `PINECONE_HOST` | — | alternative to the name: full index host URL from the console |
| `PINECONE_NAMESPACE` | — | optional; isolates datasets inside one index |
| `PINECONE_EMBEDDING_MODEL` | `llama-text-embed-v2` | dense, 1024-dim hosted model |
| `CHUNK_SIZE` / `CHUNK_OVERLAP` | `1000` / `200` | overlap must be < chunk size |
| `TOP_K` | `4` | chunks retrieved per query (per-request override allowed) |
| `MAX_UPLOAD_SIZE_MB` | `50` | streamed to disk, enforced mid-upload |
| `CORS_ORIGINS` | `*` | comma-separated; only needed for direct cross-origin API calls (the bundled UI uses the same-origin nginx proxy) |
| `UPLOAD_DIR` / `VECTORSTORE_DIR` | `backend/storage/...` | runtime data, gitignored |

> **Changing the embedding model** switches the manifest directory
> (`storage/vectorstore/<model>/`) — re-upload documents after switching. Also
> recreate/re-point the Pinecone index if its dimension differs.

## API reference

Base URL: `http://localhost:8000` (direct) or `http://localhost:3000` (through the
UI's nginx proxy) — all endpoints live under `/api`.

| Method | Path | Description |
|---|---|---|
| GET | `/api/health` | Liveness + active models + docs indexed |
| GET | `/api/diagnostics` | Manifest vs. Pinecone stats (debug missing sources) |
| POST | `/api/documents/upload` | Multipart upload & ingest (201) |
| GET | `/api/documents` | List ingested documents |
| DELETE | `/api/documents/{doc_id}` | Remove a document and its vectors |
| POST | `/api/chat` | RAG query → answer + sources |

Full schemas are in Swagger UI (`/docs`). Examples with curl:

```bash
# 1. Upload a document
curl -F "file=@./big-report.pdf" http://localhost:8000/api/documents/upload

# 2. List what's in the index
curl http://localhost:8000/api/documents

# 3. Ask a question
curl -X POST http://localhost:8000/api/chat \
  -H "Content-Type: application/json" \
  -d '{"query":"What are the main risks described?"}'

# 4. With conversation history (optional)
curl -X POST http://localhost:8000/api/chat \
  -H "Content-Type: application/json" \
  -d '{
        "query": "And the mitigation for each?",
        "history": [{"role":"user","content":"What are the main risks?"}]
      }'

# 5. Delete a document
curl -X DELETE http://localhost:8000/api/documents/<doc_id>
```

### Upload response (201)

```json
{
  "message": "Document ingested successfully.",
  "document": {
    "doc_id": "5a077245c2684e17acc95cec87f03b8a",
    "filename": "big-report.pdf",
    "chunks": 312,
    "size_bytes": 4823001,
    "uploaded_at": "2026-11-03T14:36:01.514799Z"
  }
}
```

### Chat response (200)

```json
{
  "answer": "The main risks are ...",
  "sources": [
    {
      "doc_id": "5a077245c2684e17acc95cec87f03b8a",
      "filename": "big-report.pdf",
      "chunk_index": 42,
      "page": 12,
      "snippet": "Risk factors include ...",
      "score": 0.83
    }
  ],
  "provider": "gemini",
  "model": "gemini-2.5-flash",
  "chatbot_name": "Lisa"
}
```

> `score` is Pinecone's cosine similarity — **higher is more similar**.
> `page` is present for PDFs.
>
> The `answer` text never mentions documents, files, context or `[Source N]`
> markers — it reads like Lisa simply knows the answer. The `sources` array is
> still returned separately so the frontend can show references if desired.

With no documents uploaded, `/api/chat` still replies in character (as Lisa)
with an empty `sources` list. Common errors: `409` (documents are indexed but
Pinecone returned no matches — check `/api/diagnostics`), `415` (unsupported file
type), `400` (empty file / nothing extractable), `503` (missing key / Pinecone or
Gemini unreachable), `502` (LLM provider error), `422` (invalid request body).

## Operational notes & limits

- **Pinecone inference quota** — embeddings are billed/rate-limited by Pinecone;
  bulk uploads embed in batches (96 chunks per call).
- **Document bookkeeping is local** — `manifest.json` lives on the backend node.
  Running several backend replicas against one index gives each replica its own
  document list. Keep one replica, or move the manifest to a database.
- **Scores** are cosine similarities; higher = more similar.
- **Scanned PDFs** (images, no text layer) need OCR before ingest; text-based
  PDFs work out of the box.
- **History** is client-supplied — the server is stateless; the bundled UI keeps
  the conversation in memory (last 12 messages sent as `history`) and clears it
  on refresh or **New chat**.
- **The bundled UI hides source citations** — `sources` is still in the API
  response, but the React app does not render it, so Lisa's answers never reveal
  that they came from uploaded files.
- Changing `CHUNK_SIZE`/`CHUNK_OVERLAP` only affects future uploads; re-upload to
  re-chunk.
- `PROVIDER=fake` is for tests/smoke checks only — answers are deterministic
  echoes and embeddings are fake (still requires a mocked/real Pinecone index).

## Troubleshooting

**`This index has a document schema, so writes must go through the documents API`**

Your index was created as a *document-schema* index (Pinecone's documents API /
integrated embedding). This backend stores raw vectors and needs a **standard
vector index**. Create one and point the app at it:

- **Console:** Indexes → Create index → choose the regular/custom vector index
  type (not "documents" / "integrated embedding"), dimension **1024**, metric
  **cosine**, serverless.
- **SDK** (runs inside the backend image, so no local install needed):

  ```bash
  docker compose run --rm --entrypoint python backend -c "from pinecone import Pinecone, ServerlessSpec; import os; Pinecone(api_key=os.environ['PINECONE_API_KEY']).create_index(name='chat-bot-vectors', dimension=1024, metric='cosine', spec=ServerlessSpec(cloud='aws', region='us-east-1'))"
  ```

Then `PINECONE_INDEX=chat-bot-vectors` (or the new host URL as `PINECONE_HOST`)
and restart: `docker compose up -d --build`.

**`Vector dimension ... does not match the dimension of the index`**

The index dimension must be **1024** for the supported embedding models
(`llama-text-embed-v2`, `multilingual-e5-large`). Recreate the index or change
`PINECONE_EMBEDDING_MODEL`.

**`PINECONE_API_KEY is not set` / `PINECONE_INDEX is not set`**

Set them in the repo-root `.env` (Docker) or `backend/.env` (local run), then
restart. On Linux/macOS use `export KEY=value` or a `.env` file — `$env:KEY=...`
is PowerShell-only.

**Upload succeeds, but `/api/chat` returns `"sources": []`**

The backend now answers with a `409` explaining this instead of a fake "I don't
know". Check the live state:

```bash
curl -s localhost:8000/api/diagnostics | python3 -m json.tool
```

It shows the configured index/host/namespace, what each uploaded document was
ingested into, Pinecone's actual vector counts per namespace, and `warnings`.
Typical causes (all listed there):

- documents were uploaded while `PINECONE_INDEX`/`PINECONE_HOST` pointed at a
  different index — upload them again;
- vectors are in another namespace than `PINECONE_NAMESPACE`;
- Pinecone reports `0` vectors — the writes went elsewhere;
- the index was recreated after the uploads.

**The UI shows "Offline" or an empty document list**

Check both containers and the proxy:

```bash
docker compose ps
curl -s localhost:3000/api/health   # through nginx
curl -s localhost:8000/api/health   # direct to FastAPI
```

The frontend container starts only after the backend passes its healthcheck. If
the API responds but the UI does not, rebuild the frontend image
(`docker compose up -d --build frontend`). For local dev, make sure the backend
is running on port 8000 — `frontend/vite.config.ts` proxies there.

**`413 Request Entity Too Large` when uploading through the UI**

nginx allows 60 MB per request. If you raise `MAX_UPLOAD_SIZE_MB` above that,
also bump `client_max_body_size` in `frontend/nginx.conf` and rebuild.

**I changed `VITE_API_BASE_URL` but the UI still calls the old host**

It is a **build-time** variable. Rebuild the image
(`docker compose up -d --build frontend`); a container restart is not enough.

**`"answer"` looks like `[{'type': 'text', ...}]`**

Fixed: Gemini 3.x returns structured content blocks and the API now flattens
them to plain text. Rebuild (`docker compose up -d --build`) if you still see it.
